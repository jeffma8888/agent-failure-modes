# Core rules - the prompt-sized payload

Load this file into an agent prompt (max 26 KB). It holds the practices, one distilled rule per catalog topic, and the rules of the most-recurrent incidents, distilled from 671 incidents. The complete list is RULES.md, which is not prompt-sized. Look any id up with `python3 tools/afm.py show INC-XXXX`. Generated by tools/build.py: never edit it by hand.

## Practices

- **PRA-0001 - The enforcement ladder: pick the cheapest rung that makes the failure impossible.** Any requirement can be enforced at five strengths: a skill doc, an always-injected policy line, an agent self-report token, a deterministic harness check, or structural impossibility. Cost AND reliability both rise going down. Enforce at the cheapest rung that makes the failure impossible rather than merely unlikely, and move a requirement one rung DOWN every time it is violated. A rule that has failed twice as prose belongs in code.
- **PRA-0002 - Classify a control by its enforcement point, never by its medium.** Harness, policy, guardrail and skill are separated by ENFORCEMENT POINT, not by medium. Ask what happens when the model ignores it: if nothing happens it was guidance, if the action is blocked or reverted it was a guardrail. Code the agent can edit mid-run is not harness; a human approval queue containing no code is. The test is whether the agent can change it or route around it inside the run.
- **PRA-0003 - Six conditions for a gate that cannot be skipped.** A gate runs always only if ALL six hold: its call site is in the harness and not in the prompt; invocation is unconditional; the default is fail-closed; the evidence is produced by the harness rather than reported by the agent; the gate sits outside the surface the agent can edit; and it has been proved two-sided against a known-bad sample. Drop any one and the gate silently becomes advisory.
- **PRA-0004 - Choose the constraint surface before choosing the enforcement strength.** Before arguing determinism versus capability, pick the CONSTRAINT SURFACE. Clamp the narrowest axis that makes the failure impossible AND is orthogonal to the capability you are paying for: output form, actions, blast radius, resources, the oracle, information, or identity - never the reasoning. Test: if clamping this axis to fully deterministic loses the reason you hired the model, it is the wrong axis. An apparent determinism-versus-capability trade-off is usually evidence of a coupled surface, not a law.
- **PRA-0005 - Admission control for an agent team on a shared host.** Treat the host as shared. Attribute load first: list processes by CPU and owner; the load average counts waiting work and lags. Never stop a process you do not own; ask its owner. Gate by job weight, not one limit for all. Reserve capacity for deadline-bound checks, or run them inside an admitted session. Use a first-come lock, wait for load before taking it, and run dependent steps under one acquisition. Match runtime parallelism to the serialized resource; give surplus agents static work. Log the admitting load, lock wait and holder in each receipt.

## Topic rules

One distilled rule per topic, grouped by class.

### false-green

- **A negative, absence or presence check passed for an unrelated reason:** Pair every negative or absence check with a positive control from the same read and state that must flip it, use one negative per rejection reason, assert the exact error or element rather than any match, and for a reaction assert the target is absent before the action and present after it.
- **A reported count, total or ledger does not match what ran:** Compute counts from structured sources (runner summary lines, parsed tables, the exact bytes executed) with the same formula as the earlier record, reconcile by item identity rather than totals, and cross-check any count by a second method before it reaches a verdict.
- **The gate was green but the cases it vouches for never executed:** Before citing a green, count what actually executed: cases per project, each new test file by its own marker, real commands rather than stubs, a non-empty population. A skipped, refused, setup-only or empty run is missing evidence, never a pass; a no-op outcome needs before/after proof.
- **A mutant or red-first witness does not prove what it is named for:** A witness counts only when it fails at the case's own assertion for the stated reason: trace every guard between the mutated line and the assertion, defeat each layer that enforces the rule, test redundant layers separately, state which items were witnessed, and measure mutants instead of reasoning about them. A config change that moves tests needs a red-first witness too.
- **A test oracle, locator or review claim came from memory, not source:** Bind every oracle, locator, identifier and behavior claim to its source of truth at the installed or pinned version: cite the line that renders or defines it and search for each name. Treat a fix or review claim as a new claim to verify, and review independently by deriving your own list before reading the author's. Run a new root green on unchanged code before any mutation.
- **An artifact that looks like evidence was cited but proves no fact:** Cite only evidence that directly establishes the claimed fact: open the artifact and check it holds what it claims (digests, bodies, byte equality, a runtime result), retain it, and copy every id or value verbatim from the output of the call that produced it, after that call has returned.
- **Tests pass but the real page, status or session is wrong:** Before accepting a user-facing change, observe it on the real target: walk the real build, assert HTTP status with the body from every client, prove the identity a request claims with a positive marker, render with the target renderer, run destructive probes last, and test every flow that needs what a change hides.
- **A red, blocked or failing result came from setup or environment:** Before counting a red as a finding, name the step and guard that failed and prove the code under test ran. An environment, permission, setup or earlier-guard failure is missing evidence for the claimed product defect, never proof of it and never a pass; record a broken fixture, probe or guard as its own test defect. Pair each new probe with a positive control that is green on current code.
- **A gate verdict came from a wrapper, pipe, chain or last line:** Take each step's verdict from its own status and output: set pipefail or capture status on the next line, stop a chain at the first failure, gate on step records not a wrapper's exit, fail a clean-pass control on error text, never chain a required write after a diagnostic and check the file exists, re-read a dependent write's precondition before it, and prove a failing child turns the gate red.
- **A test stays green with the behavior removed or broken:** Show each test can fail: make it establish its own precondition (the interleaving, the descendant, the dirty state), include the fixture where the two behaviors differ, and assert an observable effect that differs with and without the feature, through the real entry point, not how the code was invoked.
- **Verified a shortcut, a part or an old revision instead of what ships:** Verify the exact thing that ships with the canonical gate's own commands: the merged stack, every caller of a changed helper, the full branch range, a revision that holds the fix. A focused run, one branch or one option alone proves only itself; ask what two safe changes combined let a consumer confuse. A test that launches a runner runs it on a probe file, never the whole suite.

### stage-timeout

- **Stale or overbroad load gates block or mis-admit work:** Apply the documented freshness window and workload-specific threshold before launch side effects, stop when the gate denies, and wait only within a bounded admission loop; inspect load producers without altering unrelated processes rather than applying a full-run gate to every task.
- **Timeout policy ignores purpose, call path or lifecycle:** Define each timeout purpose, scope and rationale in the current policy, then verify it in active code on every dependent path; use group-wide lifetime and global elapsed time for global shutdown contracts.
- **Timing models or optimizations are not measured:** Base timing models and optimizations on repeated, complete measurements of the exact tree with load recorded; profile the real critical path, retain protected cases, include serial work and cold starts, and apply the required margin rather than the full deadline.
- **Work outgrows hidden caps or loses timeout headroom:** Measure all work against the smallest enforced cap on the current tree under representative load, bound growing inputs and retain measured headroom as tests change; checkpoint state-keyed progress instead of retrying the same over-budget plan.

### delegation

- **The brief or plan left a gap the worker fell through:** Close every hatch by name: forbid each escape route inline in one clause, list the only files a job may touch, define every term an independence rule uses, keep one template per role, derive dependency edges from what each file actually needs, and run a red check before the build agent starts.
- **Teammates finished on disk; the reply never came or went unnoticed:** Never treat a reply as the only signal of completion. Discriminators: when a teammate shows finished or paused, or its output file stops changing, read the file and the run state at once and grade from disk; check who spoke last per teammate instead of assuming silence means running; read a real clock; never end a turn waiting on a message alone.
- **A record is guessed or stale, or lives only in a message or worktree:** Write coordination records from the source and keep them where they survive. Discriminators: put ids, names and paths in messages only after reading them from git output, the live roster or main; refresh the roster at each phase change; put content others need in files, not messages; before cleaning a worktree, triage untracked items against main and keep what nothing supersedes.
- **Your order collided with a tool rule, permission ceiling, guard or pin:** Before issuing an order, read it against the executor's tool rules and permission ceiling and the guards or digest pins of every command and file it names; a ruling never overrides those rules, a shared service restart belongs to its owner, and the rules you write for teammates bind your own shell too.
- **The reviewer or runner you named was not independent or not free:** Name the reviewer when the artifact lands, from whoever is free; first search commits AND review files for every earlier author or judge of the item, compare the reviewer's model with the author's, and re-read the plan's independence rules - the reviewer's own author check is the second line, never the first.
- **Parallel work stalls behind one busy owner, open decision or slot cap:** Split what can proceed from what must wait. Discriminators: sign the stable re-checked part of a document and name what stays held; separate apply-now amendments from author-decides; start the red phase while a recheck runs; redo a mechanical merge yourself and prove the delta path by path; release idle teammates to free slots; dispatch gated runs the moment the window opens.

### detector-fail-open

- **The checker ran but its target coverage is unproven:** Prove intended checker scope with explicit baseline, collected-target and per-observation evidence plus known-bad and known-good controls; require known events to be observed, distinguish empty results from failed collection and scan the full publishable range before accepting silence.
- **A broken guard implementation still appears valid:** Require exact guard decisions for every protected field, tag and copy, with distinguishing positive and negative controls; treat unknown or failed reads as denial or retained data, never successful validation, and choose fixtures that separate the competing implementations.
- **Syntax matching accepts decoys or rejects valid forms:** Test detectors against equivalent valid forms and adversarial invalid forms with alias resolution and decoys; enforce the semantic condition across every candidate instead of accepting a convenient syntax shape or one allowed substring.
- **A parser or pattern reads the wrong evidence:** Prove extraction and classification against actual-format records, malformed input and adversarial decoys inside the full failure boundary; require plausible parsed values and the exact intended output evidence before trusting silence or a match.

### tooling-paths

- **A helper or runner reads your argument as a different kind or name:** Never let a tool guess what a token is: pass each item once in its one explicit form, check which name and options the runner actually takes before briefing a run, treat a selection error before any test as 'not run'; a tool that cannot tell must fail closed, never create or copy by guess.
- **A shell chain ran on after a failed step, or a refusal sank safe steps:** Validate every precondition before the first write, join dependent steps with && (never ; or a pipe into a formatter), print each step's exit status, put external and destructive writes last, split the chain at every approval boundary, and dry-run the WHOLE script on scratch copies.
- **An edit anchor or text match hit different bytes than you meant:** Treat strings as bytes the tool will interpret: quote heredocs (<<'EOF'), anchor replacements on the whole unique line and diff afterwards, put specific rewrite rules before general ones, strip escape codes and trailing padding before matching, exclude your own command from process searches, and assert the match count.
- **A relative path or link resolves from a different root than assumed:** Write paths for where the file will RUN, not where it sits now: absolute paths across worktrees, imports checked from the active destination, manifests that do not follow symlinks, and never a link whose target depends on which tree reads it - verify every link resolves inside its own tree before any test.
- **Sandbox cannot resolve or authorize the target you actually meant:** Give the sandbox only what it can check statically. Discriminators: cd only to a literal absolute path; probe code from a file inside the scratch tree, never a regex literal on the command line; scope searches to tracked files in your own tree; list every binary a profile must exec, setuid ones included; prove a path-alias fix with the default spelling and no workaround.
- **The tool's own resolution or defaults, not the target, caused it:** Pin tools by absolute path and verify each wrapper, launch form and config exists and behaves as assumed in THIS shell before relying on it; close gates only through the canonical entry; read the tool's error stream and name the failure class before attributing a failure to the target.
- **The checkout or dependency tree you ran in lacks what the job needs:** Before running or assigning work in a tree, confirm it holds the checkers, scripts and tracked files the job needs (sparse lists included) and that its dependencies install offline with a frozen install; fast-forward or use a full disposable checkout rather than patch around the gap.
- **Code valid alone fails in the host runtime, module form or generator:** Check the host before writing against it: its module form, built-in fixture names, erasable-syntax rules and generator defaults; never track a file a tool rewrites per mode; when generated output must be hand-touched, change only the named defect and record raw and delivered hashes with the diff.
- **zsh reads your variable differently: colon modifier, word split, array:** Assume zsh: brace every variable before a colon (${r}:path), never rely on word splitting of an unquoted variable, iterate arrays with the quoted all-elements form, run bash-only env scripts via bash -c, and confirm each side-effecting send by its own exit status.

### test-isolation

- **Assertion measures more than its contract: caches, order, whole totals:** Match the assertion to the contract: count only the identities the case created, never an unfiltered shared total or its delta; compare sorted copies for set membership; strip terminal codes, compare relative or resolved paths; derive expected inventories from source declarations, fail closed on a shape change; name explicitly, never by directory or pattern, the tool-owned paths a check skips.
- **Green alone, red in the full suite, with another run, or after a merge:** Own the state you assert on: count only what the test created, by name; give each run, stage and agent its own database or cluster, lifetime tied to its creator; when state cannot be private, serialize every project or group sharing it, not only files within one; teardown restores the baseline successors expect (reset then reseed), on failure too; run the full tier on the merged tip before merge.
- **Passes in a warm checkout, fails in a fresh clone, CI or other runner:** A test establishes every precondition itself (fixture in tmp_path, seed records, server, env var, full git history) and the runner owns the scratch paths its tests write to. Before calling it green, run it once in a fresh clone with nothing exported; before reading a red as a regression, run the same files under the same runner on main.
- **The red comes from the test's own fixture, tool option or control:** When a new test, control, fixture or tool option goes red, or never reaches its negative, suspect the test first: reproduce with a minimal variant or a known-good page, bisect the tool's options, compare a hand-written request with the repo helper, keep fixtures from writing outside themselves, and fix it as a tests-only change that keeps the right-reason red.

### observability

- **Timestamp labels disagree with the actual clock:** Generate each timestamp directly from a completed clock read and mechanically compare the written label with that returned value; never estimate it, type it from memory or schedule its write alongside the read.
- **A reassuring signal contradicts the underlying evidence:** Verify operational claims against fresh, complete evidence for the exact target and tree; bind probes to the actual rendered elements and inspect distributions, effective metadata and causal attribution rather than trusting a convenient signal or summary.
- **Missing evidence keeps findings unverified:** Obtain inspectable evidence from a bounded diagnostic on the actual product instead of repeating inconclusive static reviews; preserve complete item-level logs and failure channels outside scratch state, verify launch artifacts and bound required reads so summaries never substitute for evidence.

### spec-and-scope

- **Claims or instructions say more than the evidence supports:** Write each claim from the primary artifact or confirmed observation, mark unavailable facts and owner-bound gaps explicitly, and never replace missing evidence with an expected outcome or requested scope.
- **A local fix leaves sibling cases or callers broken:** Enumerate every sibling, call site, payload, and encoded rule affected by a change, then verify their exact contracts together; after a merge conflict inspect the entire merged file, including automatically resolved lines, and run the typecheck.
- **Framework behavior contradicts the design or test:** Verify framework-dependent claims in the installed source end to end and test the complete observable contract, including transformations, errors, side effects, and replaced defaults.
- **Instructions fail a gate or omit the required operation:** Walk each instruction through the installed tool and real checker on the intended post-step tree, including effects, parameters, permissions, and exact cleanup hook bodies; ask before substituting a private driver, and verify restored green through the standard runner.
- **A planned step cannot run because its prerequisite is missing:** Trace each step to its actual inputs, declared callable seams, owners, and approvals, then order required prerequisites before consumers without inventing dependencies or stubs.
- **A cited baseline, count, line, or digest no longer matches its source:** Pin derived records to current source revisions, preserve reviewed bytes, and reconcile citations, counts, rulings, and signatures against the exact source; diff unchanged ranges before reviewing the actual delta.
- **Requirements, units, or hard limits cannot hold together:** Check all requirements together on explicit units and edge cases before signing, including dependency contracts, hard size limits, producer-consumer compatibility, and final-step rounding.
- **Green tests omit or misstate required behavior:** Maintain an executable per-case inventory tying each required behavior to a collected assertion and qualifying run, with discovery witnesses, stable oracles, and whole-suite comparison after product changes.
- **Work lands under the wrong owner, path, or write boundary:** Derive each assignment and write boundary from the governing layout and ownership registry, check every affected file and dependency before dispatch, and apply a ruling to the individual files it governs rather than the whole commit.

### identity-and-keying

- **An approval or activation names the wrong commit or line of history:** Name the commit that actually holds what you assert, the first main commit holding both the review and the reviewed bytes, and judge ancestry on current main: merge main into the branch first, land bytes before the record approving them, write a marker only after its review, carry every activation a merge makes due, and run the identity check on the exact merged tree after each landing and merge.
- **A name, path string or digest stands in for the real identity, drifts:** Identify a thing by its canonical identity and derive everything else from it: compare resolved real paths not strings, verify path-to-digest pairs not membership, derive display names from ids, record the tool versions with any stored proof and compare them at use, read identities from the log rather than memory, and keep one fact per field.
- **A newly minted id or name collides with one already in use:** Before minting an identifier, check every place that kind of identifier has ever lived (history, branches, other writers' entries, generated defaults), not only the current list of survivors; namespace shared short names by owner, check uniqueness globally rather than per batch, and never key derived state on an id a rejection or rename can recycle.
- **A file-replacement (supersession) record is refused or claims too much:** A replacement record maps exactly the paths the ruling approved; its old path takes the predecessor's current form (active once activated, else the newest pending copy), its old digest the bytes on main, never an unapproved chain; the new name sits inside the family; land it with its registry line and moved file in one commit, manifest sorted; run the checker's own rule on a scratch clone first.

## Rules of the most-recurrent incidents

Ranked by occurrences (an incident plus its repeats), then severity, then id.

- **[INC-0274 / medium / 10x]** Write a recorded time from a command output, never from memory
- **[INC-0128 / medium / 5x]** Sweep the disk and read a real clock before trusting replies.
- **[INC-0650 / medium / 4x]** Write each decision invariant once, apply the same severity to every option that shares its condition, and never label a disadvantage common to all options as uniquely blocking; recompute verdicts after corrections.
- **[INC-0048 / low / 4x]** Never cite an identifier produced by a step that has not returned yet. If call B needs a value from call A, B goes in a later block and quotes what A actually returned.
- **[INC-0611 / low / 4x]** Read the clock in its own call and copy that value into the label; a rule that exists is not a check.
- **[INC-0062 / medium / 3x]** A reviewer's statement about framework or library behaviour is a hypothesis with the same standing as the author's. Verify it at the pinned version, reading the whole function, before it changes a test or a design.
- **[INC-0165 / medium / 3x]** In zsh, write the braces form of a variable before a colon.
- **[INC-0207 / medium / 3x]** Check the exit status of every send, and pass real arguments, not a packed string
- **[INC-0358 / medium / 3x]** When a ruling is restated in a spec, copy its population word for word; a qualifier borrowed from another purpose narrows an alarm, so diff every restated condition against the ruling's own words and fix each sibling copy
- **[INC-0640 / medium / 3x]** Write unverified only after every retrieval route has failed, not one endpoint: when a search tool errors, run the documented fallbacks (news feeds through the page fetcher, a direct fetch of the likely source, reference and filing searches) and list the routes tried beside the gap word.
- **[INC-0517 / low / 3x]** Before naming a reviewer, read the root coverage author line and review history; the reviewer own author check is the second line, not the first.
- **[INC-0518 / low / 3x]** A tool that accepts both root names and file paths must not guess which one a bare token is; list what it will land and compare with what was intended before it runs.
- **[INC-0658 / low / 3x]** Cite each fact to the page whose text states it (the release note that contains it, the per-item page, the specific doc), and search that page for the claim before citing; a page merely about the subject, the newest release or an index page is not support.
- **[INC-0012 / high / 2x]** In a multi-writer tree, never use `git add -A` or `git commit -a`; name paths on the commit itself and check its stat before moving on. A path-limited commit cannot protect your edits from another writer's blanket stage, so quiesce live loops before editing their tree. Undo an over-broad commit only while it is still HEAD and without changing working-tree bytes.
- **[INC-0018 / high / 2x]** A negative result from a detector is NOT evidence of health. Every alarm must be proven against a KNOWN-BAD sample before it is trusted (fires) and against a known-good sample (does not fire). Fail-open monitoring is worse than none. And know your regex flavor: `\|` is alternation in BRE but a LITERAL pipe in ripgrep - use plain `|`.
